Parallel Multi-Agent Triage

System Architecture & Pipeline Execution Model

Application Overview Sequential Orchestrator

This application implements a high-performance customer support ticket triage pipeline utilizing the Google Agent Development Kit (ADK) and Gemini 2.5. Instead of running sequentially or using single flat prompting, the system decouples distinct analysis tasks into a team of specialized sub-agents.

These sub-agents evaluate the ticket **concurrently** in a parallel phase to minimize latency, writing their conclusions to a shared state before a specialized **Router Agent** synthesizes the final routing decision and action steps.

Detailed Worker Sub-Agents Parallel Execution

Each worker sub-agent executes independently, targeting only the raw ticket text and populating its dedicated output key in the shared session state:

Sentiment Agent

Judges emotional tone of the ticket.

State key: sentiment_result
  • Sentiment Options:
  • positive
  • neutral
  • negative
  • angry
  • Output fields: confidence, evidence
Category Agent

Classifies support category.

State key: category_result
  • Category Options:
  • Billing
  • Technical
  • How-To
  • Feature-Request
  • Outage
  • Account / Other
Priority Agent

Scores ticket urgency & severity.

State key: priority_result
  • Priority Tiers:
  • P1 (Critical / Outage)
  • P2 (High)
  • P3 (Normal)
  • P4 (Low)
  • Output fields: sla_hours, reason
Reply Agent

Drafts initial responses.

State key: reply_result
  • Constraints:
  • Under 90 words
  • Acknowledge issue
  • Set direct expectations
  • No fake promises
  • Professional & warm
The Router & Synthesis Phase Final Synthesis

The Router Agent acts as the final decision maker. It is configured as the second sub-agent of the main SequentialAgent. Once the parallel branch finishes executing, the Router accesses the shared session state to read all specialist results.

It applies smart orchestration rules to merge these outputs into a single action-oriented decision schema: 

{
  "category": "Billing",
  "priority": "P2",
  "sentiment": "negative",
  "route_to": "Finance Queue",
  "escalate": true,
  "sla_hours": 24,
  "suggested_reply": "[Warm greeting] We received your message about the duplicate charge...",
  "summary": "Customer reports billing duplicate charge; request escalated to Finance Team."
}
